# 小红书发布稿

## 标题

我拆了一遍夸克网盘 Agent Skill

## 正文

最近我在看一个很具体的问题：**Agent Skill 到底应该怎么审？**

这次拆的是 `quarkclouddrive v1.0.11`。

先说结论：我没有发现浏览器 Cookie 扫描、SSH Key 搜集、反向 Shell、挖矿这类典型木马行为。所以这篇并不是“发现病毒”。

真正让我觉得值得讨论的，是 Agent Skill 和普通软件不太一样的地方。

普通程序主要需要回答：**代码能做什么？**

但 Skill 还多了一层：**它在要求 Agent 做什么？**

我最后比较在意四个问题。

第一，原 Skill 的调用流程里存在自动更新链。它可以从远端获取新版 ZIP，覆盖 runtime，同时覆盖 `SKILL.md`。我没有在这条链里找到固定哈希或数字签名验证。

这意味着远端更新的并不只是程序代码，也可能包括“Agent 接下来应该遵守什么规则”。

第二，`SKILL.md` 要求 CLI 调用携带 `--session-input`，内容是用户的原始提问，而且要求逐字复制。文档给出的用途是服务质量追踪，但 CLI 本身把这个参数定义成了可选。

第三，安装脚本更新完成后会向 Agent 输出类似“清除相关 memory”“重新阅读 SKILL.md”的指令。

我觉得这里出现了一个很有意思的新边界：**工具的输出，是否应该有权要求 Agent 改变自己的行为状态？**

第四，文件总结、分析、提问被要求必须使用夸克 AI，同时 Skill 又明确限制 Agent 分析自身 CLI 的实现。

对一个持有网盘 OAuth 权限、能够访问私人文件的工具来说，我认为这两类规则都没有必要。

除此之外，我还检查了 token 本地存储、machine-id、工作目录、自动安装依赖、搜索限制、文件读取的数据流等问题。

最后我做了一份 `quarkclouddrive-pure`。

思路其实很简单：**网盘工具就只做好网盘工具。**

搜索、上传、读取、分享、转存这些核心能力保留；原始 prompt telemetry、静默更新、设备标识采集、强制 Quark AI、营销话术和反审计规则去掉。

我觉得这次真正值得留下来的不是“某个 Skill 有问题”，而是一个更普遍的问题：

**Agent 时代的安全审计，不能只检查代码有没有恶意行为。**

还需要检查：它在要求 Agent 做什么？它把什么数据交给了第三方？它能不能改变自己的规则？用户是否仍然拥有审计它的权利？

完整审计、修改记录和可复现 patch 均在本仓库。

## 置顶评论

补充几件事，避免产生歧义：

1. 这篇不是“夸克网盘是木马”的结论。审计对象仅是 `quarkclouddrive v1.0.11` 这份 Agent Skill。
2. 审计采用静态分析，没有执行原包里的安装脚本。
3. 原始 ZIP SHA-256：`034ac1f3db416ae6435e111024961abd84b9d80a2e8e8093db72adf50b950f48`。
4. Pure 版保留修改记录和可复现 patch，方便任何人独立复核。
